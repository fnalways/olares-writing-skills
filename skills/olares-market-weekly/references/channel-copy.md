# Channel copy

Use these shapes as guidance, not as text to repeat every week. The fixed X/Facebook heading is the exception.

## Poster copy

Default hierarchy:

1. **New Apps** with the exact app name, production version or model label, and a short benefit description.
2. **App Updates** with the most useful or familiar apps given enough space for one or two sentences.
3. **Across the Market** with compact entries for the remaining updates when a secondary group helps readability.
4. Minimum system requirements and essential update reminders, only as needed.

Keep important apps visually prominent without calling the others “Also updated.” Do not divide ordinary updates into an inferior-looking security bucket.

Preserve conditions that affect truth. “Chat with coding agents through Open Terminal” is more accurate than implying that every installation gains coding agents automatically.

A small feature summary can still carry several useful benefits. For example, a chat-app entry might cover split-screen work, editable tables and Markdown, and faster loading, rather than spending the entire line on one integration.

Do not put a date, an app-count badge, a Discord label, or a decorative closing slogan on the poster by default. End with relevant requirements or notices when present.

## Discord

A practical shape is:

```text
Hey @everyone! :wave:

This week in Olares Market, [a natural opening connected to the week].

[One or two short paragraphs about useful changes.]

Get started:
[App name]: [verified public tutorial URL]
[App name]: [verified public tutorial URL]

A few things to know:
- [An action with its reason, if necessary.]
- [A specific first-use or compatibility notice, if necessary.]

[An optional natural closing.]
```

Do not make every sentence follow the pattern “App X adds feature Y.” Connect the ideas naturally and avoid repeating everything already on the image.

Keep commands out of the introduction. Place an essential first-login command in the short notes area with its purpose and the place to run it. Do not include credentials themselves.

Explain backups when migrations are involved. If rollback cannot undo a migration, say so when relevant to the audience. Do not invent this limitation for other apps.

Explain a delisting or replacement when the reason is known. Avoid implying automatic data transfer or compatibility merely because a new listing replaces an old one.

Only include hardware and download details that materially affect whether someone can try the app. The tutorial can carry the full setup checklist.

For a weekend post, “Enjoy the weekend! 👋” is an acceptable light closing. It is not mandatory, and no closing is also fine. A music-only question unnecessarily narrows a roundup that covers several kinds of apps.

Keep the post within the destination's applicable limit. For a normal Discord message, aim below 2,000 characters and split only when genuinely necessary.

## X main post

Use this exact first line by default:

```text
📢 What's New on Olares Market? | Weekly Digest
```

The main post accompanies the poster. It need not summarize every app or repeat the image's labels.

A good opening can offer a light weekly or weekend framing with a small connection to how people might use the apps. Avoid both extremes: a bare catalog of names and an abstract marketing slogan unrelated to the week.

The user liked this direction as a starting point:

```text
A little weekend browsing, Olares style. ☕️
```

It is an example, not a permanent line. If more body is wanted, add a useful thought rather than another invitation to browse or try something. Avoid repeating the same meaning in the opening, rhetorical question, and closing.

Use this thread-specific ending when appropriate:

```text
Highlights below, guides in the thread 👇
```

Count the complete post, including the fixed title, spacing, emoji, and link weighting. Use the standard X limit as the default unless long-post capability is known. If a requested longer version exceeds that limit, say so and offer a faithful shorter version. Do not claim unverified length compliance.

## X tutorial replies

Prefer one tutorial per reply, using an emoji, one useful sentence, and the verified URL. Let the link preview carry the longer documentation description.

```text
🔖 Save and organize useful pages with [App name]
[Verified public URL]
```

No mandatory numbering. Avoid turning every tutorial reply into a second announcement. A concise replacement or setup note may be added when it prevents misunderstanding. Optional operational replies are appropriate for backup or login details that would overload the main post.

## Facebook

The user normally publishes one Facebook post, not a thread and not a planned follow-up comment.

Reuse the chosen main body when appropriate. Keep the same fixed heading as X. Remove promises about a thread or comments unless that publication plan changes.

When the poster is attached, a suitable ending is:

```text
Take a look at this week's highlights below 👇
```

If tutorial links are requested on Facebook, include them in the same post. Do not invent a comment-based link strategy.
